# 段階 6P: フレームタップ (フレームごとの描画リストを JSON Lines で出す)

## 目的

攻略本ツクール (Commentarii) の観測経路「段 2 描画命令タップ」のため、Pictor がフレームごとに
描いた物を構造化データで外へ出す。画素の読み戻しをしない。既定 OFF でフレームレートに影響しない。

## 前提未確定

- Commentarii の契約 (`spec/feature/render-tap-contract.md` / `schema/render-frame.schema.json`) は
  本タスク時点で Commentarii main に無い。段階 6 依頼文「1. 描画リストの契約」を仕様として読み、
  形を `spec/feature/frame-tap.md` §3 に固定した。契約確定後に差分があれば追随する。
- `camera.viewport` は `screen_bbox` の基準を示すために足した (契約の文面に無い追加フィールド)。

## 完了条件

- C-1 parse_frame_tap_setting(value): 未設定 / 空 / `0` / `off` は無効、`stdout` / `-` は標準出力、それ以外はファイルパス
- C-2 make_frame_tap_sink(setting, error): ファイルを開けないときは null と理由を返し、無言で別経路へ逃げない
- C-3 project_world_aabb_to_screen(bounds, view_proj, viewport, out): 8 隅の投影の外接矩形を px (左上原点) で返し、視点の後ろにまたがる箱は w = ε 面で切ってから射影する
- C-4 resolve_mesh_id(info): 名前があれば名前、無ければ `fp:` + 頂点数とインデックス数の FNV-1a 64bit (16 桁 hex) を返し、名前無しを知らせる
- C-5 encode_frame_tap_line(frame, out): 改行を含まない 1 行で frame / t / camera / passes[scene, ui] / draw ごとの mesh, material[], instance, world, screen_bbox, depth_order, tags[] を出す
- C-6 FrameTap::end_frame(): scene は視点深度の近い順、ui は後に描いた順に depth_order (0 = 最前面) を振り、配送先へ 1 行渡す
- C-7 FrameTap::is_enabled(): 配送先が無ければ false で、begin_frame / add_*_draw / end_frame は何も出さない
- C-8 PictorRenderer (固定シーン: メッシュ 2 つ + UI 矩形 1 つ): タップ ON で契約どおりの 1 行が出て、OFF で何も出ず描画統計が変わらない

## 再利用探索

- `src/visus/visus_json.cpp` の JSON エミッタ: 不採用。Visus 内部ヘッダで、VisusValue 木を作ってから
  複数行に整形して出す。タップは 1 フレーム 1 行で、フレームごとに値の木を組むと確保が増える。
  数値の書き方 (`to_chars` + Android は classic locale の stream) と文字列エスケープの方針はそのまま踏襲した。
- `pictor::transform_math::multiply` / `transform_point`: 採用 (view * projection とクリップ座標)。
- `DataQueryAPI::get_mesh_info` / `VertexDataUploader::get_entry`: 不採用。線形探索なので
  draw ごとに引くと O(draw x mesh)。代わりに `register_mesh_data()` 時にハンドル添字の平坦な表へ写す。
- `CompiledBatchRecorder` の draw 発行地点: 不採用。バッチは static プールの添字を保持しておらず
  インスタンスごとの変換へ戻れないため、同じ可視集合 (カリング後の SoA) を直接読む。
- `DataExporter` (プロファイラ記録): 不採用。フレーム統計の CSV / JSON 出力で、描画リストの形を持たない。

## 変更した境界

- 新規公開ヘッダ `include/pictor/tap/*.h`。
- `PictorRenderer`: `frame_tap()` / `frame_tap_names()` を追加、`RendererConfig::frame_tap` を追加。
  `render()` と `end_frame()` にタップ有効時だけ通る分岐を 1 つずつ追加。
- `UIRenderer`: `set_frame_tap()` を追加 (既定 null、null なら従来どおり)。
- `ObjectPool`: `visibility_flags()` / `material_handles()` の const 版を追加。

## 復旧方法

- タップは観測専用で描画結果を変えない。不具合時は `PICTOR_FRAME_TAP` を外す (または
  `RendererConfig::frame_tap` を空 / `"off"` にする) と、OFF 時の分岐 1 つ以外は変更前と同じ経路になる。
- それでも戻す場合は本コミットを revert する。公開 API の追加のみで、既存 API の意味は変えていない
  (`ObjectPool` の const アクセサ追加、`UIRenderer::set_frame_tap()` は既定 null)。

## 検証

- 実施: Windows / MSVC (VS 2022 14.39) Debug でクリーンビルド (`pictor` と全テスト)。新規コード由来の警告は
  C4324 (float4x4 の 16B 整列によるパディング、既存の `Bone` 等と同種) のみ。
- 実施: ctest 全 46 件。`unit_frame_tap_test` は Pass (C-1〜C-8 を検査)。失敗 3 件
  (`unit_visus_resource_loader_test` / `unit_compiled_graph_wiring_test` / `fps_baseline_test`) は
  変更前の HEAD (0d82888) を別 worktree でビルドしても同じく失敗する (本変更と無関係)。
- 実施: `fps_baseline_test` (タップ OFF、50000 オブジェクト) の平均フレーム時間を単独実行で比較:
  変更前 28.6 ms / 変更後 28.0 ms・28.5 ms (Debug)。OFF 時の分岐 1 つで差は出ていない。
- 未実施: GCC (Ubuntu) のローカルビルド。手元の WSL (Ubuntu) はディスクのマウントで起動できず、
  Docker デーモンも起動していない (サービス起動は本タスクの範囲外)。CI (build.yml、GCC) は `pictor`
  ライブラリのビルドまで (テストは CI でも回らない) なので、GCC でのテスト実行は未確認のまま残る。
  GCC で問題になりやすい箇所 (`_dupenv_s` / `fopen_s` は `_MSC_VER` 限定、浮動小数点 `to_chars` は
  GCC 11 以降で可、Android は classic locale の stream) は目視で確認した。
- 未実施: UIRenderer::record() 経由の UI 記録の実行確認 (Vulkan デバイスが要るため headless テスト不可)。
  テストは UIRenderer が呼ぶのと同じ `FrameTap::add_ui_draw()` を直接呼んで確認した。
- 未実施: Commentarii の `schema/render-frame.schema.json` での検証 (スキーマが未作成)。形はテストで確認。
- Augur の `contract-wrap` は TypeScript / JavaScript 専用で C++ に注入できないため、契約 C-n は
  `unit_frame_tap_test` のアサーションで判定している。
