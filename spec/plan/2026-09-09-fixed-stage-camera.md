# Fixed camera inside stage presentation

The four-panel dance production needs both fixed and moving cameras. Previously disabling `--stage` was the only way to stop its orbit/dolly, but also restored the debug HUD and disabled stage-specific presentation. Add `--stage-fixed-camera`, which enables stage presentation while keeping yaw and distance constant. It retains stage lighting, animated backdrop, the head/body target choice and HUD suppression. The existing moving mode remains a look-at orbit of +/-12 degrees and a 10% dolly driven by recording time.

The change lives solely in reconstruction options and camera calculation. No public motion ABI, renderer precision algorithm or character animation changes are needed. Build the polynomial demo SDK in the dedicated worktree and install an isolated HQ package for Figmentum. Native visual verification belongs to the consuming Figmentum production through Excubitor in its body directory with Concordia claim/release.

Validation: MSVC Release polynomial SDK build and isolated install passed. Figmentum linked this package and captured all four 960x960 views, 725 frames each, at quality 8 / 0.125px tolerance through Excubitor with claim/release. Every final capture diagnostic reported zero unresolved hits. The fixed close and fixed wide proof images and final beginning/middle/end composite were inspected: stage presentation remains clean without the debug HUD, while the fixed camera path has constant yaw/distance. The consuming wide-view containment guard passed all frames. No unit-test suite or native launch from a worktree was performed.
