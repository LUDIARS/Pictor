是正提案（3 点）

1. Memory — GPU プール数の記述ずれ 要修正

spec/subsystem/memory.md は GPU アロケータを「用途別 4+1 プール」とし、表に indirect（16MB / ring / per-frame reset）を 5 番目のプールとして掲げ、暗に allocate_indirect() 相当を期待させる。一方、実装 include/pictor/memory/gpu_memory_allocator.h のプールは 4 本のみ：

// gpu_memory_allocator.h
GpuAllocation allocate_mesh(...);      Pool mesh_pool_;
GpuAllocation allocate_ssbo(...);      Pool ssbo_pool_;
GpuAllocation allocate_instance(...);  Pool instance_pool_;
GpuAllocation allocate_staging(...);   Pool staging_pool_;
// allocate_indirect() / indirect_pool_ は存在しない

indirect draw buffer は専用プールではなく allocate_ssbo()（SSBO プール）から確保される。 なお Config::indirect_buffer_size = 16MB フィールドだけは残っており、専用プールに 結び付いていない。

提案: spec を実装に合わせ「4 プール（mesh / ssbo / instance / staging）。indirect は SSBO プールから サブアロケート」と訂正するか、逆に実装側へ indirect_pool_ + allocate_indirect() を 追加して config フィールドと整合させる。前者（ドキュメント訂正）が低リスク。

2. Decal — 定数の配置 軽微

spec/subsystem/decal.md はコンパイル時定数 kMaxDecals = 64 に言及するが、 実体は公開ヘッダではなく src/decal/decal_system.cpp 内に定義されている。 機能上の問題はなく、文書の精度上の指摘に留まる。consumer が上限を参照したい場合は ヘッダへ昇格すると良い。

3. C API — README とビルド設定の不整合 要修正

README.md はビルドオプション表に PICTOR_BUILD_C_API（C ABI エクスポート）を 列挙しているが、CMakeLists.txt には対応する option() もターゲット定義も無い。 実体 include/pictor/c_api.h と src/c_api/c_api.cpp は存在するため、 「ソースはあるがビルド配線が無い」状態。

この乖離は spec/setup/build-options.md が既に正直に注記しており、spec の自己整合性は高い。 提案: README から当該行を外すか、CMakeLists に option(PICTOR_BUILD_C_API ...) + pictor_c_api ターゲットを追加して README に合わせる。

系統A / 系統B についての補足

レビューで特筆すべきは、spec が Pictor のレンダリングパイプラインを 2 系統に分けて 正直に記述している点。これは「誇張しない」設計姿勢の表れであり、レビュー対象としても健全：

系統A — 宣言データ

PipelineProfileDef（pass 列 / post_process / shadow / GI / memory 等）。 *.profile.json で完全に外部化済み・ツール編集可。プロファイル選択・pass 順序・ メモリ/更新/GI/GPU駆動/プロファイラの設定値は実ランタイムに反映される。

系統B — 実描画

実 VkRenderPass チェーン / framebuffer / draw 記録。一部は依然ハードコード。 post-process の既存エフェクトのパラメータ・on/off は build_post_process_config() ブリッジ経由で実描画に届く。Phase 3 で scene 側 attachment の汎用化が進行中。

spec はこの A↔B の「未配線」領域を各所で明示している （例: shader_override / render_targets は構造体に格納されるが scheduler 未消費）。 レビュー上、これらは「バグ」ではなく「設計上の段階的実装の宣言」として扱った。

検証方法

  • 各 spec が主張するクラス・interface・struct・enum・file:line 参照を抽出。
  • include/pictor/<name>/ ・ src/<name>/ ・ CMakeLists.txt を Glob/Grep/Read で突合。
  • シンボルの存在・シグネチャ・構造体フィールド・enum 値・既定値・CMake オプション行番号を確認。
  • 判定: 一致 / 軽微 / 要修正。
